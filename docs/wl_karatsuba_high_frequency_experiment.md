# Karatsuba 双核 185/190/200 MHz 实验

日期：2026-09-17。状态：185/190 MHz 已通过内部验收，200 MHz 实验进行中。

起点为 `reports/wl_lowcost_modmul/karatsuba_frequency/20260917/targeted180/routed.dcp`，保留原始 180 MHz 结果和源文件。器件 xc7vx485tffg1761-2，Vivado 2026.1；当前为两个 2-path 核，固定模数 Q=2^60-2^14+1，64 位接口。

## 执行顺序

1. 对 180 MHz 已布线检查点复查 180/185/190/200 MHz，保存各频点最差 50 条建立路径和 20 条保持路径。复查不改变布线。
2. 从保留检查点开始，依次尝试 185/190/200 MHz 的物理优化。优先保持 RTL、14 拍模乘、II=1 和 8623 拍完整计算不变。
3. 若当前布线上的物理优化失败，检查新关键路径，再选择未布线检查点重新布局/物理优化/布线。
4. 若 200 MHz 的实际失败路径证明需要修改算术结构，再在隔离快照中验证局部 RTL 候选，先做算术与系统回归，再综合实现。增加流水不属于默认操作。

## 验收边界

每个候选分别记录建立/保持余量、脉宽检查、全部网络布线情况、内部未约束端点、DRC 错误、LUT/FF/Slice/DSP/BRAM、检查点 CRC、脚本归档哈希和受保护输入哈希。实现完成不等于时序通过，失败尝试保留。

只认可内部静态时序；外部 IO 延迟、板级引脚/标准尚未完成，因此不宣称板级签核、实测功耗、实测执行时间或全局 Fmax。原始 Karatsuba 基线综合控制台的目录错误继续继承并显式记录，不将其改写为无错误综合。

## 备用局部 RTL 构思（仅数学验证，尚未实施）

190 MHz 最差路径经过低字求 m、修正量相关进位链，再到 correction_s1 的同步 R 端。当前 RTL 的分支条件是 `d == 0`。对本固定模数，d=floor(m*(2^14-1)/2^16)，因此 d=0 当且仅当 0<=m<=4。令 x=T[15:0]，逆映射得到 x 属于 {0000,3fff,7ffe,bffd,fffc}。

等价的提前判断为 `(x==0) || ((&x[13:2]) && (x[15:14] == ~x[1:0]))`。这种写法可能绕过分支控制上的 m/d 进位链，但综合是否改善面积/时序需要另测，不能当作已实现收益。

`scripts/prove_wl_correction_zero.py` 已对全部 65536 个 x 校验 d、提前零判断和完整 correction，与独立整数除法公式一致，零失配；结果在 `early_correction_zero_proof.json`。仅生成数学证据，未改生产 RTL、实验快照、流水或黄金数据。
