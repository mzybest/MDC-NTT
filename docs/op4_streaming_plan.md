## 1. 第一版的目标与范围

第一版验证单次完整多项式乘法内的连续流动：每拍两项点乘结果直接进入每拍两项的 RN 逆变换，不经过 C_NTT 整帧写回/读回。允许以后为实际连线增加少量固定寄存器。

保留已有自然序 A/B 装载、Pre、Q64 WL 运算和 fused Post 缩放语义。输入装载 RAM 仍存在。首版不承诺每 2048 拍启动下一组完整乘法任务，因为本帧 INTT 会复用下一帧 Forward 所需资源。

数据流：

```text
A RAM -> Pre -> Forward A --+
                           +-> PW(2项/拍) -> I0 -> I1 -> ... -> I11 -> Post
B RAM -> Pre -> Forward B --+
```

逆变换的逻辑级编号 I0..I11 与原物理级 S0..S11 分开；不使用整条 S11->S0 反向切换。

## 2. 已演练的具体资源分配

以下时间均以当前顶层接受 compute start 为 0。表中时间是该逆逻辑级第一次/最后一次接受蝶形输入。

| 逆逻辑级 | 物理算术资源 | 输入前每条 FIFO 深度 | 蝶形首拍 | 蝶形末拍 |
|---|---|---:|---:|---:|
| I0 | A.S0 蝶形 | 0 | 2271 | 4318 |
| I1 | B.S0 蝶形 | 1 | 2287 | 4334 |
| I2 | pool lane2 + 新增加减/对齐逻辑 | 2 | 2305 | 4352 |
| I3 | pool lane3 + 新增加减/对齐逻辑 | 4 | 2324 | 4371 |
| I4 | 新增蝶形 0 | 8 | 2347 | 4394 |
| I5 | 新增蝶形 1 | 16 | 2378 | 4425 |
| I6 | 新增蝶形 2 | 32 | 2425 | 4472 |
| I7 | 新增蝶形 3 | 64 | 2504 | 4551 |
| I8 | 新增蝶形 4 | 128 | 2647 | 4694 |
| I9 | 新增蝶形 5 | 256 | 2918 | 4965 |
| I10 | A.S1 蝶形 | 512 | 3445 | 5492 |
| I11 | A.S11 单位因子蝶形 | 1024 | 4484 | 6531 |

I1 保留 B.S0 的额外边界寄存器；I11 保留 A.S11 的额外边界寄存器。其余蝶形按 15 拍建模。最后保留 14 拍输出对齐。

模型对复用单元检查的是上一任务整个算术流水已排空，而非仅检查上一任务停止发起。可复用资源的最小空闲间隔为 193 拍。当前分配没有同拍双重占用。

只新增 6 个通用模乘器；pool lane2/3 的两个蝶形适配器还需要加减、sum 延迟和各自的有效控制，不能把它们视为零面积。DSP 若维持现有每个 WL 模乘 20 个 DSP 的映射，则粗估为 520+120=640；这不是综合结果。

## 3. FIFO 与控制如何拆分

逆变换每一级先通过 C2 配对，再进入 GS 蝶形。深度依次为 0、1、2、4、...、1024。

- I1..I10 首版使用独立的两条 FIFO，总计 `2*(1+2+...+512)=2046` 个 64 位 delay words，约 16 KiB。
- I11 复用 A.S0 原有两条深度 1024 的 FIFO。它们在第 3101 拍排完 Forward 尾部，逆变换数据第 3460 拍才进入，相隔 358 个完整空闲周期。
- 本次模型用同一对持久化队列先处理 Forward，再处理 I11，没有清空队列数据；有效输出没有带出旧 token。
- 首版不将输入 A/C bank 同时重构成上述多条小 FIFO。后续若做这种优化，必须重新证明并发端口和 bank 映射。不能直接从当前 59 BRAM 扣掉 8 个。

关键控制变化：一个物理 stage 不能只有一个统一的 NTT/INTT 模式位。

例如第 2271 拍 A.S0 蝶形已经开始 I0，但 A.S0 原有 C2 还要排出 Forward 尾部直到第 3101 拍。因此至少分开：

1. BFU 输入源、因子源、输出目的地的所有权。
2. C2 输入源、输出目的地、配对计数和 flush 状态的所有权。

BFU 转入 I0 后，其结果送往逆链；原 C2 继续自己的 Forward flush，不接受新 I0 valid。各资源确认旧结果排空后，装载新的局部计数/配置。既不全局 reset，也不清空整块 RAM 数据。

现有 pool 的全局 `if Pre / else PW / else Post` 请求及单个 op tag 不满足新分配。lane0/1 保留 PW、随后 Post；lane2/3 同期接收 I2/I3，必须改成分 lane 的请求和返回标记。

## 4. 配对、twiddle 和 Post 的准确规则

PW 第 r 拍产生自然频域索引 `rev11(r)`、`2048+rev11(r)`；把它们视作位反转数组的相邻位置 `2r`、`2r+1`。

对逆逻辑级 j，令 `t=2^j`。第 r 个蝶形的数组位置为：

```text
group = floor(r/t)
k = r mod t
a_position = group*(2*t) + k
b_position = a_position + t
twiddle_exponent = rev11(group)
```

等价的局部 ROM 索引：`rev_(11-j)(r >> j)`，该 ROM 存储 `omega^(-2^j * index)`。I11 因子恒为 1，现有 A.S11 单位因子旁路可保留。

所有因子在 RTL 中必须使用 Montgomery 表示。首拍因子为 Montgomery 1；同步 ROM 须提前预取下一拍地址。首版为不同逻辑级提供独立可用的读口：I0 的原 A.S0 因子存储已空闲；其余冲突处先用独立 ROM。ROM 双口共享、B 核正向表派生逆因子属于后续微综合比较，不能在当前面积估算中当作免费。

I11 输出第 r 拍的自然索引是 `[r, r+2048]`。Post 必须使用这两个索引，而非原来的 `rev11(r)`。

保留 Post 中 `N^-1 * psi^-index` 的整体缩放。不要同时引入 OP4 的逐级除 2，否则重复归一化。

## 5. 目前模型的整机时间线

| 事件 | 首拍 | 末拍 |
|---|---:|---:|
| 当前 Forward 核输出 / PW 输入 | 2257 | 4304 |
| PW 输出 / I0 输入 | 2271 | 4318 |
| 逆核心输出（含 14 拍尾部对齐） | 4514 | 6561 |
| Post 写结果 | 4528 | 6575 |
| done | 6576 | 6576 |

当前 8623 拍 -> 候选 6576 拍，减少 2047 拍。较前一步 6575 的条件估算多 1 拍，来自显式保留 B.S0 的边界寄存器。若真实路由增加寄存器，周期表必须相应更新。

150 MHz 下仅作换算约 43.84 us；尚未证明新设计能达到 150 MHz。自然装载阶段保持 4096 拍时，load+compute 估算为 10672 拍。外部结果读出不在此口径。

## 6. 从模型到可实现设计的执行顺序

### A. 架构模型：已完成

数值、配对、全部输出顺序、连续输出窗口、物理算术生命周期、最深 FIFO 的无数据清零复用已检查。没有运行新的 RTL，也没有运行 Vivado。

### B. 固定 RN 逆变换 RTL：下一步

在实验模块中实现 C2-before-BFU，复用 `gs_butterfly`、`delay_memory` 和 WL 模乘。先固定逆链，暂不包含 Forward 运行时资源切换。

用实际 Forward/PW RTL 轨迹的 Montgomery 数据驱动，并与完整 4096 项 golden 对比；加入随机和定向数据。Questa 检查：

- 每帧接收/产生恰好 2048 对，首/末拍与模型逐项对齐。
- 所有蝶形的配对索引及 twiddle 索引与模型一致。
- Post 结果自然索引、Montgomery 域和 N^-1 缩放正确。
- 多帧测试不 reset；检查第一拍、最后一拍以及 FIFO flush。

通过标准是数据与时序均符合模型。若不通过，先修改设计/模型并解释差异，不改变 golden。

### C. 部分共享的实验顶层

按第 2 节物理表整合真实双 Forward -> PW -> RN INTT -> Post。生产顶层保留作对照，实验顶层独立命名。

落实 BFU/C2 独立所有权、pool 分 lane 路由、ROM 首拍预取、结果地址。加入可执行断言：

- 同一 BFU、ROM 读口、FIFO 端口不被两个任务同拍驱动。
- 资源切换时上一所有者已经排空；旧 valid/flush 不进入新上下文。
- PW 每一项仅被逆链接受一次，正确对应频域索引。
- 单帧流入逆链后不出现中途气泡；输出数和 done 正确。
- 连续完整任务之间无需全局 reset，下一次 Forward 恢复正确。

这一步用 Questa 即可，Vivado xsim 也能做同类功能仿真；无需先做布局布线。

### D. Vivado 物理验证

先对新增 BFU 选择器、pool 适配器、共享 FIFO 和 ROM 读口方案做微综合，发现 RAM 推断或资源意外膨胀后再集成。之后以相同 FPGA、工具、约束对实验整机综合和布局布线。

必须输出层级 LUT/FF/DSP/BRAM、RAM 归属、拥塞/关键路径、WNS/TNS 和完整路由报告。首个约束点沿用 6.667 ns，不能把单次正 WNS 换算称为正式 Fmax。

### E. 与现有候选按统一口径裁决

| 候选 | 当前证据 | 用途 |
|---|---|---|
| 现有双 Forward | 8623 拍、已布线结果 | 基线 |
| 缓存后 4-path INTT | 固定逆链 RTL；整机约 6575 拍投影 | 资源复用对照 |
| 本文 2-path RN 流式 | 完整数值/调度模型；6576 拍投影 | 无 C_NTT 整帧等待候选 |

当前模型下，流式方案单次延迟并不优于 4-path 投影，却新增约 6 个模乘。因此不能仅以“流水不停顿”选它作为最终高性能方案。只有实际存储、能耗、输入接口或连续任务吞吐等目标有可验证收益，或者进一步调度显著降本，才有充分理由采用。

若最终目标是批量持续吞吐，应另测连续任务启动间隔和长期吞吐，并补齐 Pre/PW/Post 并发与输入带宽；不能拿单次 compute cycles 替代。
